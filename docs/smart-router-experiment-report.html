aware-gateway：从 Prompt 决策到 Safe Control 的路由实验

Coding agent 在一个任务里往往会调用模型几十次。aware-gateway 放在 agent 和模型供应商之间， 把这些调用变成可路由、可计费、可追踪、可复盘的事件。第一阶段先用 prompt 让决策模型判断 该用便宜模型还是强模型；第二阶段把高置信、低风险动作从 prompt 决策里拿出来，交给确定性 safe-control 规则处理。

第一阶段的核心经验：prompt 决策可以跑通，但 prompt 不能承担所有控制责任。 真实 trial 暴露出一个主要矛盾：很多调用只是读文件、搜索、跑现成测试，却仍然要付一次 decision model 的固定税。第二阶段把这类高置信动作下沉成 safe-control 规则，让 prompt router 专注处理真正不确定的推理节点。

1. 为什么需要一个模型网关

Coding agent 做一个任务时，通常不是一次模型调用结束。它会读文件、搜索线索、改代码、跑测试、 解释失败、再继续修。一个 trial 里几十次模型调用很常见，而这些调用的风险和价值并不一样。

如果 agent 直接绑死一个模型，就只剩两个粗暴选择：全程用最强模型，质量稳但贵；全程用便宜模型， 成本低但容易在关键步骤错。aware-gateway 的目标是把“模型选择”从 agent 里抽出来，变成一个可观察、 可替换、可实验的控制层。

为什么 trace 是核心功能？

省钱实验最怕“感觉便宜”。必须把每个 trial 的 agent trajectory、gateway trace、provider cost 和 verifier reward 对上，才知道 cost per solved 是否真的下降。

2. 第一阶段 Prompt 决策架构

第一阶段的 smart-router 是一个 prompt-based router。它不改 agent 的规划方式，也不训练新的 classifier。 每次 agent 发起模型调用，网关把当前调用压缩成一个结构化 prompt，交给决策模型，然后把返回的 JSON 解析成最终路由决策。

Prompt block 包含什么 为什么需要
Request snapshot 最新用户/agent 消息、system prompt 片段、message count、粗略 token 规模。 判断这一步是在读上下文、写代码、恢复错误，还是准备最终收敛。
Model menu z-ai/glm-5.3-flash 与 anthropic/claude-opus-5 的价格、能力和上下文窗口。 把选择空间固定成“便宜档 vs 强模型档”，避免中间模型干扰实验解释。
Decision policy 便宜优先、关键路径升级、连续恢复要控制预算、最终验证不要省错钱。 把“省钱”改写成更具体的操作规则，而不是一句模糊目标。
Recent memory 最近 5 轮的 selected model、turn type、hypothesis state、critical path、context summary、reason。 避免每次决策都像第一次见到任务；让 router 知道刚才已经试过什么。
Output schema model、turn_type、hypothesis_state、critical_path、recoverability、context_summary、reason。 保证结果可解析、可审计、可 replay，而不是只得到一段自然语言解释。 
agent request
  -> gateway extracts request snapshot
  -> prompt = model menu + policy + recent memory + output schema
  -> decision model returns JSON
  -> parser validates selected model
  -> proxy sends request to selected provider
  -> trace/audit stores cost, route, reason, and session id

当前实验故意把菜单收窄到两档模型：z-ai/glm-5.3-flash 和 anthropic/claude-opus-5。这让每次决策都足够清楚：这一步到底值不值得花 Opus 的钱。

运行时选择 当前配置 用途
Decision model openai/gpt-5.6-sol 产生结构化路由决策，替代已移除的 Qwen3-27B endpoint。
Cheap model z-ai/glm-5.3-flash 工作先验：智能水平约为 Opus 的 75%，但输入/输出单价约低 71x/100x。
Premium model anthropic/claude-opus-5 质量锚点，用在高风险推理、恢复和最终收敛。

3. 第二阶段 Safe Control 验证

Prompt-only 路由跑通以后，下一步不是继续堆 prompt 形容词，而是回到真实 trace： 哪些决策需要智能判断，哪些只是控制系统应该直接处理的确定动作。这里按三个朴素原则推进： 实事求是，先看真实 trial；实践检验，用同一任务重跑；抓主要矛盾，先消掉“每步都问决策模型”的固定税。

Phase 2 的目标很窄：不降低 shadow-relay 的 verifier reward，同时减少 semantic decision model 调用。safe-control 只处理高置信动作：读文件/搜索、跑已有测试、固定格式输出、 重复同一错误后的单次升级、假设被反证时升级、连续 premium 后的冷却，以及最终完成确认兜底。 没命中的请求仍然交给原来的 prompt-based smart-router。

验证环节 结果 说明
确定性 probe 9/9 场景命中预期；9 次 agent trace，2 次 decision trace，6 次 safe-control，1 次 guardrail。 不调用真实模型，用 mock provider/decision endpoint 验证控制逻辑、audit trace 和分析口径。
第一次真实 pilot 手动中断在 21 次 agent 调用，成本约 $1.34，质量未判定。 这不是质量证据，但暴露了两个真实问题：traceback 指纹太粗，固定格式规则会误吃实现类请求。
修复后真实 pilot reward=1.0，861.8s，22 次 agent 调用，成本 $2.2468。 Opus 6 / Flash 16；decision 10 次；safe-control 11 次；completion guardrail 1 次；所有 provider 调用 200。
实验中发现的问题 修复 验证状态
分析器看不到 safe-control，导致“decision calls 下降”说不清来源。 CSV 增加 safe_control_rule_call_count、safe_control_rule_ids、safe_control_bypass_rate。 已验证：本轮输出 file_read_search_cheap:11，bypass rate 0.5。
重复错误升级用到了过粗的 traceback 指纹，容易把不同错误都看成同一个错误。 指纹优先提取具体错误行，并且同一 fingerprint 只自动升级一次；后续同错交回语义 router。 已验证：单元测试覆盖 specific traceback line，真实 pilot 没再出现连续同错升级。
“只返回 JSON”这类固定格式规则可能误判实现/编辑请求。 固定格式和读文件规则遇到 implement/edit/patch 等实现语境时不本地降级，改交给 decision model。 已验证：新增回归测试，probe 中 ambiguous implementation fallthrough 到 decision model。
Flash 很便宜，但单次调用仍可能输出很长、耗时很久。 本轮先记录为下一阶段问题：路由结果需要携带 max_tokens、超时和输出预算。 待做：真实 pilot 最大单次 latency 122.7s，这不是模型选择本身能解决的。

第二阶段目前的判断：safe-control 不是让 router “更聪明”，而是让它少在确定性动作上消耗智能。 这轮最有价值的信号是：同一主任务通过 verifier，成本从第一阶段最好 live run 的 $2.68 降到 $2.25， 同时 semantic decision model 从几乎每步调用降到 10/22。

4. 实验设计：少跑，但对照点要清楚

最早的设计想跑大矩阵：多个任务、all-flash、all-premium、smart-router、多次重复。 真实执行后我们缩小范围。关键不是“跑了多少行表格”，而是 smart-router 相对强模型参照 是否有清晰、可解释的质量/成本信号。

7. Prompt 变体真正说明了什么

prompt 变体的价值不是给每个版本排榜，而是暴露 router 的决策机制。到目前为止，最重要的发现是： 成本信息必要但不充分；能力先验太粗；关键路径和最近历史比单轮分类更有用。

Prompt 思路 真实 run 信号 这轮学到什么
Cost-aware shadow-relay 通过，但成本 $6.26，agent 路由 Opus 24 / Flash 4。 把价格写进 prompt 会提醒 router，但不会自动形成好策略。模型为了安全仍会大量选 Opus。
Flash = Opus 75% intelligence shadow-relay 通过，但成本 $6.87，agent 路由 Opus 21 / Flash 7。 能力先验有用，但仍然太粗。router 需要知道任务阶段，而不是只知道两个模型强弱比例。
Critical-path budget shadow-relay 通过，成本 $2.68，agent 路由 Opus 9 / Flash 5。 最好的 live 信号：把 Opus 留给关键假设和收敛，把 flash 用于机械探查和便宜验证。
History-aware shadow-relay 通过，agent 路由 Opus 7 / Flash 16，成本 $4.45。 最近 5 轮决策摘要让 router 有“路线感”。即使成本不是最低，它给出了更可泛化的控制结构。

8. 为什么 Decision Replay 很关键

真实 benchmark run 很贵。decision replay 的做法是冻结已有 agent 轨迹，只替换 router prompt， 观察同一段上下文下新 prompt 会怎么选模型。这样可以先便宜地筛选路由策略，再把最有希望的版本拿去跑真实 Harbor trial。

Replay 方向 模型分配 读法
Cost-aware 482 条决策上下文；有效 481；Flash 253 / Opus 228。 离线会更愿意用 flash，但真实 run 仍保守，说明目标还不够结构化。
Critical-path budget 20 条 smoke replay；Flash 10 / Opus 10。 小样本里开始把 Opus 集中到关键路径，是 live pilot 成本下降的前奏。
History-aware 482 条决策上下文；有效 480；Flash 364 / Opus 116。 最强离线信号。最近历史比单轮上下文更能改变 router 行为。

replay 告诉我们“同样的上下文下可能怎么选”；live run 告诉我们“这样选会不会改变后续轨迹并影响质量”。 二者必须一起看。只看 replay 容易过度乐观，只看 live run 又太贵、太慢。

9. 经验

  1. 先修 trace，再谈 benchmark。 如果 session id、agent trajectory、gateway trace、provider cost 对不上，后面的成本结论都不可靠。
  2. 不要用 all-flash 证明 smart-router。 all-flash 是成本下界，不是好产品策略。真正的问题是何时值得升级到强模型。
  3. 把 router 当控制器，不是分类器。 单轮 prompt classification 太浅。更好的 router 需要任务阶段、最近决策、恢复预算和冷却规则。
  4. 把确定性动作从 prompt 决策里拿出来。 读文件、搜索、跑已有测试这类低风险动作，不需要每次都问一个 LLM judge；本地规则更便宜，也更稳定。
  5. 负样本要立刻反哺控制规则。 这轮真实 pilot 暴露的 traceback 指纹和固定格式误判，都已经变成回归测试；实验不能停在“看见问题”。
  6. 优化目标是 cost per solved。 便宜调用变多本身没有价值；只有 verifier reward 不下降，成本下降才有意义。

10. 下一步：从 prompt 调参走向状态化路由

下一轮不应该继续做创可贴式 prompt 微调。更好的方向是把 smart-router 明确建成一个小型状态机： orientation、mechanical_probe、critical_hypothesis、 recovery、finalization。每个状态有不同的默认模型、升级条件和预算上限。

Phase 2 之后，状态机还要能约束一次调用本身：cheap route 不只选择 flash，还应该带上 max_tokens、超时、是否允许长推理、以及超限后的升级策略。否则便宜模型也可能用长输出把时间和上下文吃掉。 

1. 离线 replay：
   - 冻结已有 decision contexts
   - 比较 history-aware、recovery-budget、cheap-validation-before-second-Opus

2. 真实 Harbor pilot：
   - shadow-relay / safe-control + budgeted stateful router / 2 attempts
   - one short generalization task / safe-control + budgeted stateful router / 1 attempt

3. 成功标准：
   - reward 不下降
   - cost per solved 接近或低于 $3-$4
   - Flash 集中在 orientation / mechanical probe / bounded validation
   - Opus 集中在 critical hypothesis / finalization / high-risk recovery
   - cheap route 的长输出和长等待被预算显式限制

Reproducibility: 这份报告只保留支撑主线判断的证据。历史 V3/canary runs、 原始 run logs 和生成的 lab 页面仍可用于审计，但不作为主证据。公开参照来自 Harbor leaderboard 的 task-level Opus 5 明细；本地成本优先来自 gateway trace 的 upstream_inference_cost。
