核心结论很短：smart-router 的价值真实存在，但不是“便宜模型越多越好”。 在 shadow-relay 上，它可以稳定通过，并且 warm-start / critical-path budget 这类策略能把成本压到一个可接受区间。但在 vpp-loss-divergence 上，本地 reduced-time 协议暴露出长路径和 provider tail 风险，继续把它作为主要 prompt 研究任务并不划算。

统计口径

数据来自两个位置：仓库内 artifacts/ 的 V3 记录，以及 /mnt/data2/aware-gateway-runs/ 的 V4 真实 run / replay / HTML 报告。 统计时按逻辑 trial 去重；同一条 canary 既保存为 harbor-canary-analysis.csv 又保存为 experiment-id 文件时，只算一次。

V4 主实验：哪部分能直接比较

V4 主矩阵原计划是 10 个 trials，实际完成 9 个。它的目标不是刷榜，而是在同一个 aware-gateway + Terminus2 + OpenRouter + reduced-time protocol 下观察 smart-router 的质量和成本。 这批数据里，shadow-relay 是干净的正样例；vpp-loss-divergence 更像可行性边界样例。

Decision Replay：为什么值得继续做

离线 replay 的价值是把 agent 轨迹冻结，只改 router prompt。这样我们先研究“同一个上下文下， 不同提示词会怎么选模型”，再决定是否花钱做真实 Harbor rerun。

history-aware-v148248074.6%364116最强的离线信号：最近 5 轮决策摘要显著改变模型分配。

replay 告诉我们“可能怎么选”，live run 告诉我们“这样选会不会改变后续轨迹并影响质量”。 二者必须配合看。history-aware-v1 离线看起来非常省 Opus， 真实 shadow-relay run 也通过了，但成本仍有 $4.45，因为少数 Opus 大上下文调用很贵。

目前判断

  1. 继续用 shadow-relay 做 prompt 研究。 它足够难，有多阶段推理、验证和恢复；又足够短，不会每次吞掉几个小时。
  2. 暂时不要把 vpp-loss-divergence 当主任务。 它适合作为压力测试，不适合快速迭代路由提示词。
  3. history-aware 是正确方向。 最近 5 轮决策摘要让 router 有“路线感”，能看到刚才为什么升 Opus、是否已经连续 premium stalled。
  4. 下一步不是简单调一句 prompt。 应该把路由决策拆成状态机：orientation、mechanical probe、critical hypothesis、recovery、 finalization，并给连续 recovery 设置预算、冷却和便宜验证要求。

下一轮建议

下一轮用两个短任务做小矩阵：shadow-relay 作为正样例， 再选一个比 vpp-loss-divergence 短、但仍有 hidden/generalization 风险的任务作为泛化样例。 每个 prompt 先跑离线 replay，再只把最有希望的 1 到 2 个 prompt 做真实 Harbor run。 

1. 冻结已有 trajectory，继续离线 replay：
   - history-aware-v1
   - history-aware + recovery budget
   - history-aware + cheap validation before second Opus

2. 真实 Harbor pilot：
   - shadow-relay / best prompt / 2 attempts
   - short generalization task / best prompt / 1 attempt

3. 成功标准：
   - reward 不下降
   - cost per solved 接近或低于 $3-$4
   - Flash 不是盲目增多，而是集中在 orientation / mechanical probe / bounded validation
