Background: Terminal-Bench 4.0 Leaderboard

Terminal-Bench 4.0 is a benchmark by Stanford / Harbor / Laude Institute that measures AI agents' ability to complete real-world software tasks in a terminal environment. 66 tasks across 7 categories (Software, Science, ML, Operations, Security, Hardware, Media), each graded pass/fail by an automated verifier. An agent runs inside a Docker container, interacts with the terminal, writes code, and must pass all tests to count as solved.

Resolution Rate = fraction of 66 tasks the agent fully solved (all verifier tests pass). No partial credit — a task is either solved (1) or not (0).

  1. Cost ≠ quality. Sonnet 5 spent $9,600 (most expensive) but only achieved 12.4% — worse than Grok 4.6 at $3,600/20.3%.

Goal

Can aware-gateway's task-router reduce total LLM cost without sacrificing response quality, by choosing cheaper models when they're "good enough" for the current turn?

We simulated a harbor terminus_2 agent loop — the same pattern used in Terminal-Bench 4.0 — for 5 generic software engineering tasks. Each task runs 5 turns with growing conversation history (prompt tokens increase from ~250 to ~700 as the agent accumulates context).

Agent Loop (5 turns per task)

Turn 1: Understand — "Read the task, summarize what needs to be done"
Turn 2: Plan     — "Create a step-by-step implementation plan"
Turn 3: Code     — "Implement step 1, write the core code"
Turn 4: Review   — "You ran the code, got this output: ... Analyze"
Turn 5: Fix      — "Fix issues and write the final version"

Each turn appends the assistant's response to the conversation history, so prompt tokens grow naturally (~250 → ~700).

Quality Scoring

Each response is scored by counting how many task-specific keywords appear (e.g., "script", "html", "sanitize" for html-js-filter). Higher = more relevant response. This is a proxy for "did the model understand and address the task" — not a full verifier pass.

Key Findings

1. Cheap models beat expensive on quality — 4 out of 5 tasks

GLM-5.3-flash scored higher quality than GPT-4o on html-js-filter (7.6 vs 4.4), vllm-streaming (4.6 vs 3.0), vf2-speedup (5.6 vs 4.4), and embedding-drift (4.8 vs 4.4). The reason: GPT-4o generates shorter responses (avg 177 completion tokens vs 500 for flash), covering fewer task-relevant keywords. For these ≤5h tasks, flash's verbose responses are more useful.

2. all-cheap saves 96% with equal or better quality

Total cost: $0.004 (flash) vs $0.098 (GPT-4o) — a 24x cost reduction. For simple-to-medium tasks, the cheapest model is not just adequate — it's optimal.

3. gateway-router saves 24% but upgrade is wasteful for these tasks

The mixed strategy (flash for turns 1-2, GPT-4o for turns 3-5) costs $0.074 — 24% less than all-expensive. But quality didn't improve: 5.0 vs 4.4 average. For ≤5h tasks, upgrading to GPT-4o on coding turns adds cost without proportional quality gain. The router should learn to stay on cheap models longer.

4. Token usage: flash generates more, GPT-4o is terse

Flash consistently uses all 500 max_tokens. GPT-4o stops early (88-394 tokens). This means flash provides more detailed plans/code (useful for agents that need to execute them), while GPT-4o's brevity may miss implementation details. Cost per useful token favors flash heavily.

Implications for aware-gateway

What the gateway should do next

  1. Default to cheapest — for ≤5h tasks, flash is both cheaper and higher quality. The router should start with flash and only upgrade when it detects the task is genuinely hard.
  2. Quality signal — the router needs a real quality signal (not just keyword count) to decide when to upgrade. Candidate: re-prompt a cheap model to self-grade, then upgrade only on low self-confidence.
  3. Context-length awareness — as turns accumulate, prompt tokens grow. The router should factor total context into cost projections: "if I stay on flash for 50 more turns at ~2K tokens each, that's $0.04; switching to GPT-4o would cost $1.25."
  4. Integration with harbor — set OPENAI_BASE_URL=http://aware-gateway:12026/v1 and pass trial/step names via extra_headers. The gateway handles model selection, cost tracking, and trace queries transparently.

Reproduce

# Run benchmark (75 calls, ~10 min)
